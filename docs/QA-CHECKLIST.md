# Visor 2.1.0-dev — ручной QA-чек-лист

Эти проверки нужно выполнить на реальном ПК с Windows: в среде разработки приложение
не запускалось (оно меняет настройки дисплея, хуки клавиатуры и автозагрузку).
Отмечайте результат: ✅ ок · ❌ баг (с описанием и строкой из `%AppData%\Visor\Visor.log`) · ➖ не применимо.

Автоматическая верификация фаз 1–8 (build/test/code review) и честный статус ручного прогона: [PHASE-8-FINAL-REPORT.md](PHASE-8-FINAL-REPORT.md).

> **Разделы оболочки.** Сейчас сайдбар: **Home / Games / Presets / System / Network / Tools** (+ Settings как диалог). Этап 1 плана 2.1 переименует их в **Home / My PC / Games / Optimize / Network / Monitor / Settings** (Presets → вкладка в Games, Tools → History/Log в Settings, System → My PC + Optimize). После Этапа 1 обновите названия разделов в пунктах ниже; смысл проверок не меняется.

## 0. Подготовка
- [ ] Сделайте копию `%AppData%\DisplayProfileManager` (старые настройки) — на всякий случай.
- [ ] Запомните текущие разрешение, частоту, план питания, Digital Vibrance и устройство вывода звука.
- [ ] Закройте старый Display Profile Manager, если он запущен.

## 1. Установка и обновление
- [ ] `Visor-Setup.exe` запускается **без** запроса UAC и без установки .NET.
- [ ] Предлагается папка `%LocalAppData%\Programs\Visor`; Browse добавляет подпапку `Visor`.
- [ ] Галочка «Удалить старый Display Profile Manager» убирает старую программу, ярлыки и задачу планировщика, но `%AppData%\DisplayProfileManager` остаётся.
- [ ] Попытка установить в непустую чужую папку отклоняется с понятным сообщением.
- [ ] Повторный запуск Setup поверх установленной версии: предлагает закрыть запущенный Visor, обновляет файлы, ярлыки остаются.
- [ ] В «Приложения и возможности» есть запись Visor с версией из `Directory.Build.props` и правильным размером; удаление работает, папка и `Uninstall.exe` исчезают через несколько секунд.
- [ ] Удаление во время активной игровой сессии восстанавливает дисплей (запускается `--emergency`).
- [ ] Portable-архив: распаковка в папку с пробелами и кириллицей в пути, запуск работает, звуки и паки находятся.

## 2. Первый запуск и миграция
- [ ] Настройки из `%AppData%\DisplayProfileManager` перенесены в `%AppData%\Visor` (профили, пресеты, хоткеи сохранились; старая папка не изменена).
- [ ] Мастер первого запуска: язык выбран по языку Windows; «Запускать с Windows» выключен по умолчанию; шаг «Найти мои игры» находит установленные игры; мастер можно закрыть крестиком/Esc.
- [ ] Нет тоста «GPU: NVIDIA» и долгого сплэша; окно открывается в видимой области экрана.
- [ ] После мастера окно не исчезает в трей (если не включено «Запускать свёрнутым»).
- [ ] Повторный запуск exe при работающем Visor показывает «Visor уже запущен» и открывает окно.
- [ ] Автозапуск: включение в Settings создаёт запись `Visor` в `HKCU\...\Run`; выключение убирает её; ошибка показывается, а не глотается.

## 3. Главное окно, окна и диалоги
- [ ] Sidebar: Home / Games / Presets / System / Network / Tools; Settings открывает диалог; Pause и Reset display внизу сайдбара. Ctrl+1..6 переключают разделы, Ctrl+K — палитра команд, Ctrl+F — поиск в Games, Del — удаление с подтверждением.
- [ ] Network: адаптер/IP/шлюз/DNS без секретов; тип/статус/скорость локализованы; шлюз в комбо отключён без gateway + toast `net.gateway.missing`.
- [ ] Network ICMP: Start/Stop; мин/мед/макс/avg/loss/jitter; Stop показывает частичную сводку; при 0 ответов — пояснение про ICMP ≠ нет интернета.
- [ ] Network DNS: «Resolving…», Stop сохраняет уже полученные строки; системный DNS не меняется.
- [ ] Network: уход с вкладки / закрытие в трей / Exit отменяют пробы; смена языка обновляет «Шлюз по умолчанию» в комбо.
- [ ] Home Suggestions: paused / Game Mode off / not High perf (Ultimate не предлагать) / conflicts+Night Light / no gateway / empty library / crash restored; пустое состояние; Apply для Game Mode и power через SafeAction (подтверждение + Undo на System); conflicts — только Dismiss; Dismiss сохраняется; автоприменения нет.
- [ ] System: Overview показывает CPU/RAM/GPU/OS/диски без выдуманных температур; Refresh обновляет; Game Mode и High performance требуют подтверждения и имеют Undo; список процессов обновляется вручную и только читается (кнопки «End process» больше нет).
- [ ] SafeAction — неудача честная: если схема High performance недоступна (ноутбук с Modern Standby), показывается ошибка, а не «применено»; повторный клик не теряет Undo.
- [ ] SafeAction — Undo переживает перезапуск: примените Game Mode и High performance, выйдите из Visor (Exit) и запустите снова — Undo доступен и возвращает именно прежнее значение (в т. ч. «значения не было»); журнал отката лежит в `%AppData%\Visor`.
- [ ] SafeAction — блокировка во время игры: при активной игровой сессии Apply/Undo недоступны с пояснением (и в System, и в Home Suggestions); после выхода из игры снова доступны; план питания после игры соответствует снапшоту сессии, а Undo SafeAction после этого не ломается.
- [ ] Home: карточки Session / Display / Library / Status показывают реальные данные Visor (не заглушки); Recent games и Recent activity обновляются после apply/pause; «Full history» открывает Tools → History.
- [ ] Home не обновляется, пока окно свёрнуто в трей (хоткеи и старт игры не вызывают перечисление адаптеров и WMI); после показа окна карточки актуальны.
- [ ] Ctrl+K: фильтр по играм и командам, Enter выполняет, Esc закрывает; Pause / Reset display / Scan / переход к Network / переход к игре работают.
- [ ] Tools → History: список из `history.json` (apply / restore / pause / emergency), пустое состояние локализовано.
- [ ] Games: один список; редактор с вкладками Display / Color / Session / Companions; sticky Apply / Launch; ⋯ — Duplicate/Export/Import/Restore и Overlay/Edit presets.
- [ ] Размер окна: при 1366×768 @125 % и 1920×1080 @150 % все основные кнопки видны без прокрутки; нет горизонтальной прокрутки.
- [ ] DPI matrix: 100 % / 125 % / 150 % — главное окно, Settings, Wizard, палитра Ctrl+K открываются в work area; Save/Apply не обрезаны.
- [ ] Высота ~768 px: Settings/Wizard/Theme помещаются (прокрутка внутри, не обрезание кнопок).
- [ ] Multi-monitor clamp: сохранённые границы на отключённом мониторе → primary; Maximize не перекрывает taskbar.
- [ ] Прокрутка: длинные формы прокручиваются локально, колесо мыши над списками не «застревает».
- [ ] Положение окна запоминается; после отключения монитора, на котором было окно, оно открывается на доступном экране.
- [ ] Перенос окна между мониторами с разным DPI: нет размытия и скачков размера (PerMonitorV2).
- [ ] Все диалоги (удаление, импорт, сброс, выбор процесса, компаньон, тема, промпт оверлея) открываются по центру родителя, закрываются Esc/крестиком, не уходят за главное окно.
- [ ] Отключённые кнопки/слайдеры выглядят отключёнными; фокус с клавиатуры виден; Tab циклирует сайдбар ↔ содержимое раздела (не застревает на странице).
- [ ] Закрытие окна сворачивает в трей и один раз показывает уведомление об этом.
- [ ] Светлая тема и русский язык: ничего не обрезано, контраст нормальный, меню трея в цвет темы.

## 4. Games (профили)
- [ ] Поля «Разрешение» и «Лимит FPS» показывают значение и позволяют ввести своё; неверное разрешение отклоняется.
- [ ] Зависимые поля блокируются при снятой галочке «Менять разрешение/план питания».
- [ ] План питания: «Не менять», стандартные планы и «Текущий план (custom)» для нестандартных GUID.
- [ ] Поиск фильтрует «живой» список; удаление/добавление при активном поиске ведёт себя корректно.
- [ ] Duplicate создаёт копию «… (copy)», выключенную, с новыми ID и без хоткеев.
- [ ] Удаление профиля: подтверждение + «Отменить» в тосте работает.
- [ ] Компаньоны: Edit/Remove активны только при выделении; режимы показаны словами, а не `scheduledTask`.
- [ ] Импорт пака с компаньонами/путём к exe: компаньоны вырезаны (есть запись в логе), пак с `processName: explorer.exe` отклонён.

## 5. Presets
- [ ] Выделенный пресет = тот, что в редакторе (имя, хоткей, слайдеры).
- [ ] Последний пресет игры удаляется и не возвращается после перезапуска.
- [ ] Хоткей: Tab уходит из поля, Esc отменяет ввод, Backspace очищает; конфликт блокируется с сообщением, какой привязке он мешает.
- [ ] Повторное применение пака из галереи не дублирует пресеты.
- [ ] Сводка пресета читаемая («Яркость +10 · Гамма 1.10 · 1440p»), хоткей показан один раз.

## 6. Игровая сессия (главное)
Проверьте с одной игрой, у которой включены разрешение, план питания, пресет при старте и компаньон.
- [ ] Старт игры: профиль применяется один раз; в логе один снапшот сессии.
- [ ] Хоткеи пресетов в игре: срабатывают **один** раз на нажатие, в т. ч. в играх с raw input (CS2, Valorant); мышь X1/X2 работает; зажатая клавиша не «строчит».
- [ ] При смене пресета поверх игры появляется OSD-баннер на мониторе игры и исчезает сам.
- [ ] Alt+Tab с «мягким восстановлением»: рабочий стол нормальный, возврат в игру восстанавливает разрешение **и** план питания.
- [ ] Если игра сама сбросила разрешение (например, при сворачивании) — Visor возвращает его в течение ~2 с, не более 3 раз в минуту.
- [ ] Выход из игры: разрешение, частота, план питания, вибранс, звук, HDR, яркость — всё как до игры; то, что профиль не менял, не тронуто (проверьте устройство связи в звуке).
- [ ] Ваш собственный лимит FPS в NVIDIA Control Panel для игры сохраняется, если профиль его не задаёт.
- [ ] Компаньон, запущенный Visor, закрывается; тот же exe, запущенный вручную до игры, **не** закрывается.
- [ ] Игра с несколькими процессами (лаунчер + игра): завершение лаунчера не сбрасывает сессию.
- [ ] Два профиля подряд (игра A → игра B без выхода): после выхода из B всё возвращается к состоянию **до A**.
- [ ] Force apply из трея: профиль применяется, в трее появляется «Остановить: …», остановка восстанавливает всё.
- [ ] Reset display (аварийный сброс) при отсутствии сессии **не** меняет разрешение и план питания, только цвет.

## 7. Выход и выключение
- [ ] Exit из трея во время игры восстанавливает всё и завершает процесс быстро (<10 с).
- [ ] Exit из трея без игры: разрешение и план питания не меняются.
- [ ] Перезагрузка Windows во время игры: после входа Visor восстанавливает снапшот без сообщения «после краша»; калибровка гаммы/ICC не сброшена.
- [ ] Принудительное завершение (`taskkill /f`) во время игры, затем запуск: восстановление по `active-session.json`, файл после успеха удалён.
- [ ] Повреждённый `active-session.json` (испортите вручную): переименован в `.corrupt-*`, приложение запускается.

## 8. Конфигурация
- [ ] Ручная правка `profiles.json` в блокноте подхватывается; правка с опечаткой **не** затирает файл и не ломает `.bak`.
- [ ] `profiles.json.bak` всегда валиден после серии сохранений.
- [ ] Компаньон на сетевом диске (`Z:\…`) остаётся в конфиге (помечен в логе), но не запускается.

## 9. Мультимонитор (если есть второй монитор)
- [ ] Профиль с целевым монитором DISPLAY2: меняется и восстанавливается именно он.
- [ ] Оверлей (Live overlay) открывается на мониторе игры; сохранённая позиция, ушедшая с экрана, возвращается на видимый монитор.
- [ ] Зум (hotkey) центрируется на мониторе игры, а не на стыке экранов.
- [ ] «Только основной монитор» отключает именно второстепенные, и всё возвращается после игры.

## 10. Производительность и ресурсы
- [ ] В простое (без игры) CPU Visor в Диспетчере задач ≈ 0 %, память стабильна после часа работы.
- [ ] После 20 открытий/закрытий диалогов и переключений вкладок память не растёт заметно.
- [ ] `Visor.log` не растёт бесконечно (ротация при ~2 МБ).
- [ ] Ввод в играх не лагает при включённых хоткеях.

## 11. AMD (если есть AMD-видеокарта)
- [ ] Приложение не падает при старте и при смене вибранса; выбирается подключённый дисплей.
